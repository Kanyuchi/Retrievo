Root causes 4 defects explain most failures

Relative asset paths break every deep link Critical

index.html loads ./assets/index-C-5aQF_5.js. On any nested URL the browser requests /jobs/assets/… or /legal/assets/…, the SPA fallback returns HTML (content-type: text/html, 200), no script runs, and the React root stays empty — a blank white page with no console error.

Affects: refresh on /jobs/:id, /settings/*, the invite link /join/:token, and all three legal pages. Top-level routes (/chats, /datasets, …) load only because they have one path segment.

Fix · set Vite base: '/' (or <base href="/">) so script/CSS tags are absolute; optionally make the server return 404 for */assets/* misses so this can't silently regress.

Public demo backend is down Critical

GET /api/stats, /api/papers, /api/documents, /api/search, /api/chat all return 503 {"error":"Internal server error"}. The Dataset, Chat, Search and Files pages therefore fail, the home page shows "0 papers" while the switcher claims 85 docs / 14,590 chunks, and every page load fires /api/stats twice and fails twice.

Job-scoped endpoints (/api/jobs/*) on the same host are healthy, so this is the demo collection's vector store / DB connection, not the API process.

Fix · check the demo collection's database/vector-store connection and the /api/stats handler; add a health endpoint (/api/health currently 404) so this is visible from monitoring.

PDF upload sends a placeholder bearer token Critical

The upload request to POST /api/jobs/:id/upload/async carries Authorization: Bearer __cookie_session__ (literal string). The backend tries to validate it as a JWT and answers 401 {"error":"Invalid or expired token"} even seconds after a fresh session. Every other call in the app omits the header and authenticates by cookie successfully.

Reproduced twice, including immediately after a successful token refresh. No document can be added to a knowledge base through the UI right now.

Fix · drop the Authorization header in the upload client (cookie auth already works — a hand-built cookie-only request reached the validator and got a field-level 422, not 401), or have the backend fall back to the session cookie when the bearer value is the sentinel.

Access token expiry is not handled in-session High

About an hour in, every API call started returning 401 Not authenticated (/api/jobs/22/clear, then /api/auth/me and /api/jobs). The UI showed "Knowledge base not found · Not authenticated" instead of re-authenticating. A hard reload fixed it: the boot sequence calls /api/auth/refresh (200) and continues. Console at boot also logs Failed to fetch user: Not authenticated and Failed to refresh auth: Refresh token missing before recovering.

Fix · add a 401 interceptor in the API client that calls /api/auth/refresh once and retries; redirect to login only if refresh fails. Silence the expected first-load 401 noise.

Suggested order of work

Fixing the four root causes turns all 10 broken checks into working ones without touching the stubbed settings pages.
  1. Absolute asset paths in the build (unblocks deep links, invite links, legal pages, refresh on any KB).
  2. Restore the demo collection's backend dependency behind /api/stats, /papers, /search, /chat, /documents; add /api/health.
  3. Remove the Bearer __cookie_session__ header from the upload client.
  4. 401 → refresh → retry interceptor; auto-dismissing toasts that don't cover the header.
  5. Then decide per settings page (Model providers, MCP, Team, Profile, Agents) whether to wire or hide — today they present mock data as if it were the user's.

Method: every route was opened both by in-app navigation and by direct URL; every button, menu item, toggle, form and modal was clicked; network requests and console output were recorded per action; the upload was tested with a real 1.6 KB PDF; expired-session behaviour was observed naturally after ~60 minutes. Test data (knowledge base "AUDIT-TEST KB", id 22, and an empty Google Drive connection) was created and removed again; the account is back in its original state with the Public Demo Collection selected and language set to English. Log-out was the only control not exercised.
